What it does

Six capabilities in one endpoint

A single POST /analyze call returns everything a clinician needs to act.

BEI Scoring
Entropy-weighted biomarker energy sum. Module A (17 markers) or Module B (KILL-4). Returns score, zone, tipping marker, and per-marker tipping contributions.
AUC 0.812 — Davoudian et al. 2023
Immune Phenotyping
SRS1/SRS2-aligned classification from IL-10 (raw), CRP, and SOFA. Detects HYPERINFLAMMATORY, IMMUNOPARALYSIS, and MIXED/TRANSITIONAL states with a confidence level.
IL-10 raw >50 pg/mL + SOFA ≥6 → IMMUNOPARALYSIS
ICD-10-CM Linkage
Three levels: per-marker, per-phenotype, and per-rule. Outcome-sensitive — R1 PASS returns N17.9 (AKI) while R1 TRIGGERED returns M62.50 (muscle wasting).
Marker · Phenotype · Rule-outcome levels
Hard Clinical Rules
Five deterministic safety rules: U:Cr catabolism (R1), IL-10 steroid contraindication (R2), DIC/ISTH gate (R3), CRRT per KDIGO (R4), protein target (R5).
R2 TRIGGERED overrides any steroid recommendation
PDF Lab Parsing
Upload a blood report PDF. PyMuPDF extracts structured marker values, merges with any JSON overrides, and runs full BEI analysis in one round-trip.
POST /extract/pdf · POST /analyze/pdf
Longitudinal Tracking
PostgreSQL-backed patient histories. Re-submit labs for the same patient ID to build a BEI trajectory. Full FDA audit trail — immutable, timestamped, hospital-attributed.
GET /patients/{id}/analyses for history

Authentication

One header, every request

Each hospital tenant receives a unique API key at registration. Pass it as X-API-Key in every call.

Keys are rotatable without downtime via POST /hospitals/{id}/rotate-key. The admin key (set via ADMIN_API_KEY env var) is never issued to tenants.

# Analyze a patient's markers curl -X POST https://your-api/analyze \ -H "X-API-Key: hosp_abc123..." \ -H "Content-Type: application/json" \ -d '{ "patient_id": "ICU-007", "markers": { "CRP": 210, "IL-10": 3.2, "SOFA": 11, "D-dimer": 3200, "Lactate": 4.2 }, "include_xai": true }'
